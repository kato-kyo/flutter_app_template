# MVP要件定義書

## 概要

MVPとは「Minimum Viable Product（実用最小限の製品）」の略で、最小限の機能で市場に投入できる製品バージョンを指します。 このドキュメントでは、Routine Managerの初期リリースに含める最小限の機能セットを定義します。

## MVPの目的

- **検証したい主要な仮説/アイデア**: シンプルなタスク管理、リマインダー、ゲーミフィケーション（バッジ）により、ユーザーが日々のルーティンや習慣を継続しやすくなるか。
- **収集したいユーザーフィードバック**: コア機能（タスク登録・表示・完了、カテゴリ管理、通知、バッジ）の使いやすさ、有効性に関するフィードバック。
- **達成したいビジネス目標**: コアコンセプトの市場受容性を検証し、将来的な機能拡張（認証、同期など）の判断材料を得る。

## 主要ユーザーストーリー

MVPで対応する主要なユーザーストーリーを優先度順にリストアップします。

### 最優先（Must Have）

1. **タスクの登録**
   - **As a** ユーザー
   - **I want to** 新しい日次または週次のタスクを、タイトル、カテゴリ、リマインダー時刻と共に登録したい
   - **So that** 実行すべきタスクを忘れずに管理できる
   - **受け入れ基準**: タスク情報（繰り返し種別、タイトル、カテゴリ[任意]、リマインダー時刻[任意]）を入力し、保存できる。保存されたタスクが一覧に表示される。
2. **タスクの確認**
   - **As a** ユーザー
   - **I want to** 今日または今週やるべきタスクの一覧を見たい
   - **So that** その日に何をすべきか把握できる
   - **受け入れ基準**: アプリ起動時に当日（または指定した期間）のタスクがリスト形式で表示される。未完了/完了状態がわかる。
3. **タスクの完了**
   - **As a** ユーザー
   - **I want to** 完了したタスクにチェックを入れたい
   - **So that** 進捗を記録し、達成感を得られる
   - **受け入れ基準**: タスク一覧で完了/未完了の切り替え操作ができる。状態が保存され、表示に反映される。
4. **リマインダー通知**
   - **As a** ユーザー
   - **I want to** タスクに設定した時刻に通知を受け取りたい
   - **So that** タスクの実行を忘れないようにする
   - **受け入れ基準**: タスクに設定されたリマインダー時刻になると、デバイスにローカル通知が表示される。
5. **カテゴリによる整理**
   - **As a** ユーザー
   - **I want to** タスクを分類するためのカテゴリを作成・編集・削除したい
   - **So that** タスクを整理し、管理しやすくする
   - **受け入れ基準**: カテゴリの作成、名前の編集、削除ができる。タスク登録/編集時にカテゴリを選択できる。
6. **モチベーション維持 (バッジ)**
   - **As a** ユーザー
   - **I want to** タスクを継続的に完了することでバッジを獲得し、獲得したバッジを確認したい
   - **So that** モチベーションを維持し、習慣化を促進する
   - **受け入れ基準**: 特定の条件（例: X日連続で全タスク完了）を満たすとバッジ獲得の通知が表示される。獲得したバッジの一覧画面が存在する。
7. **タスク・カテゴリの管理**
   - **As a** ユーザー
   - **I want to** 登録済みのタスクやカテゴリの内容を編集したり、不要になったものを削除したい
   - **So that** 常に最新の状況に合わせてタスク管理ができる
   - **受け入れ基準**: 既存タスクおよびカテゴリの編集・削除操作ができる。変更が保存され、一覧表示に反映される。

### 重要（Should Have）

- MVPにおいては上記 Must Have に集中。

## MVP対象外の機能

以下の機能は初期MVPには含めず、将来のイテレーションで対応予定です：

1. **ユーザー認証・アカウントシステム**
   - 理由: MVPではローカル完結のシンプルさを優先。
   - 予定: Phase 2以降、データ同期機能と合わせて検討。
2. **データ同期（クラウドバックアップ等）**
   - 理由: MVPではローカル完結とし、実装の複雑さを避ける。
   - 予定: Phase 2以降、認証機能と合わせて検討。
3. **カレンダー表示**
   - 理由: MVPではシンプルなリスト表示に集中。
   - 予定: ユーザーフィードバックに基づき検討。
4. **Web版、Desktop版**
   - 理由: MVPはモバイルアプリに限定。
   - 予定: 未定。

## MVP技術スタック

### フロントエンド

- Flutter ([バージョン未定])
- 主要パッケージ:
    - 状態管理: flutter_riverpod
    - ローカルDB: hive, hive_flutter
    - ローカル通知: flutter_local_notifications
    - パス取得: path_provider
    - ID生成: uuid
    - 日付/時刻処理: intl

- MVPではバックエンドは使用しない。

### データ保存

- ローカルストレージ方式: Hive

    - 獲得バッジ一覧画面
