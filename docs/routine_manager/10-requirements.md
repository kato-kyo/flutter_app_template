# 要件定義書

## 1. はじめに

### 1.1 目的

毎日の繰り返しタスクと週ごとのタスクを効率的に管理し、ユーザーの習慣化と目標達成を支援するシンプルなモバイルアプリケーションを開発する。

### 1.2 対象ユーザー

日々のタスクや習慣を効率的に管理したいと考えている社会人や学生。

### 1.3 プロジェクトの背景

多忙な現代において、日々のルーティンや習慣を維持・管理することの重要性が高まっている。しかし、既存のツールは多機能すぎたり、操作が複雑だったりする場合がある。そこで、シンプルで直感的に使えるルーティーン管理アプリの需要があると考えた。

## 2. 機能要件

### 2.1 コア機能

- **タスク管理**
    - **タスク登録:** 毎日の繰り返しタスク、または週次の繰り返しタスク（曜日指定）を登録できる。
    - **タスク編集:** 登録済みのタスクの内容、繰り返し設定、カテゴリ、通知設定などを編集できる。
    - **タスク削除:** 登録済みのタスクを削除できる。
    - **タスク一覧表示 (リスト形式):** 今日実行すべきタスク、および今週実行すべきタスクをリスト形式で表示する。将来的にはカレンダー形式表示の追加も検討する。
    - **タスク完了管理:** 各タスクの完了/未完了状態を簡単に切り替えられる。
    - **タスク分類:** タスクにカテゴリ（例: 仕事, プライベート, 学習など）を設定できる。

- **通知機能**
    - **当日朝のリマインダー:** ユーザーが指定した時間に、その日実行すべきタスクの概要を通知する。

### 2.2 ユーザー管理

- **ユーザー登録/認証方法:** [Phase2以降] メールアドレスとパスワードによる認証。パスワード忘れ時のリセット機能も提供する。
- **ユーザープロファイル管理:** [Phase2以降] ユーザー名、メールアドレスを表示・編集する。
- **ロール/権限:** 全ユーザーが同等の権限を持つ（管理者権限などは設けない）。

- 高: 最重要機能、MVPに必須
- 中: 重要だが初期リリースには必須ではない

**MVP対象:**
- ○: 最小実用製品(MVP)に含める機能
- ×: MVPには含めない機能（将来のイテレーションで実装）

## 3. 非機能要件

### 3.1 パフォーマンス要件

- **レスポンスタイム期待値:** 主要な画面遷移や操作（タスク完了など）は1秒以内。
- **並行ユーザー数:** 初期段階では考慮しない（個人利用想定）。
- **データ量想定:** ユーザーあたり数千件のタスクデータを許容。

### 3.2 セキュリティ要件

- **認証方式:** [Phase2以降] メール/パスワード認証。パスワードはハッシュ化して保存。
- **データ暗号化要件:** [Phase2以降] 通信はHTTPSを使用。ローカルに機密情報を保存する場合は暗号化。
- **セキュリティ基準:** OWASP Mobile Top 10 等のガイドラインを意識。

### 3.3 ユーザビリティ要件

- **アクセシビリティ基準:** Flutter標準ウィジェットの基本機能を活用。
- **対応言語:** 日本語
- **操作性の要件:** シンプルで直感的な操作が可能であること。主要な操作は3タップ以内で完了できること。
- **表示形式:** まずはリスト形式のタスク表示を実装する。

### 3.4 互換性要件

- **対応OS/バージョン:**
    - iOS: 最新から過去2世代程度（開発開始時に確定）
    - Android: APIレベル 21 (Android 5.0) 以上
- **対応画面サイズ:** 一般的なスマートフォンサイズに対応（タブレット最適化は初期段階では行わない）。

### 3.5 スケーラビリティ要件

- 初期リリースでは大規模スケーラビリティは考慮しない。
- 将来的なユーザー増加に応じて対応を検討する。

## 6. 用語集

- **ルーティン:** 日々または週ごとに繰り返される一連のタスクや習慣。
- **タスク:** 実行すべき具体的な行動や作業。
- **カテゴリ:** タスクを分類するためのラベル（例: 仕事, プライベート）。
- **リマインダー:** 設定された時間にタスクの実行を促す通知。
- **MVP:** Minimum Viable Product (最小実行可能製品)。早期に価値を提供するための最小限の機能セット。
