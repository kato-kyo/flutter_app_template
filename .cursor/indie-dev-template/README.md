# 小規模開発テンプレート

## 概要

このテンプレートは、小規模開発プロジェクトを体系的に管理するためのテンプレート集です。
アイデア出しから計画、開発、テスト、デプロイまでの全てのフェーズを体系的に文書化し、効率的なプロジェクト管理を可能にします。

## 利用方法

### 1. プロジェクト開始時

1. **テンプレートをコピー**:
   - フォルダ(`.cursor/indie-dev-template`)を、docs配下に、プロジェクト名のフォルダ(`docs/{プロジェクト名}/`)として、コピーします。

2. **基本情報の設定**:
   - 各テンプレートファイル内の `[プロジェクト名]` などのプレースホルダーを実際の情報に置き換えます
   - 特に `01-planning.md` の基本情報セクションから更新を始めてください

### 2. ドキュメント作成の流れ

以下の順番でドキュメントを作成・更新していくことをお勧めします：

1. **プロジェクト計画** (`01-planning.md`):
   - プロジェクト概要、ビジョン、目標、スコープを定義
   - スケジュール概要とイテレーション計画を立案

2. **要件定義** (`10-requirements.md`):
   - 機能要件と非機能要件を詳細に定義
   - 機能一覧表を作成し、優先度と担当者を割り当て

3. **MVP要件定義** (`20-mvp-requirements.md`):
   - 最小限の実用製品(MVP)に含める機能を選定
   - 主要ユーザーストーリーの詳細化

4. **基本設計** (`30-basic-design.md`):
   - アーキテクチャ設計、データモデル設計、UI/UX設計
   - テクニカルスタックの決定

5. **開発管理** (`40-development.md`~):
   - スプリント計画とタスク管理
   - `41-sprint-backlog.md` をコピーして各スプリントのバックログを作成
   - 複雑なタスクは `42-task-management.md` をベースに詳細管理

6. **機能設計書** (`45-feature-design-doc.template.md`):
   - 複雑な機能ごとに詳細設計書を作成

7. **テスト計画** (`50-testing.md`):
   - テスト戦略とテストケースの作成

8. **デプロイメント** (`60-deployment.md`):
   - リリース計画と手順の文書化

### 3. スプリント管理

1. 新規スプリント開始時:
   - `sprints` フォルダを作成し、その中にスプリント番号のフォルダを作成（例: `sprints/01/`）
   - `41-sprint-backlog.md` をコピーして `sprint-[番号]-backlog.md` として配置

2. タスク詳細管理:
   - 複雑なタスクは `42-task-management.md` をベースに `task-[スプリント番号]-[タスクID].md` として作成
   - 作業ログ、発生した問題、解決策を記録

### 4. カスタマイズ

プロジェクトの性質や個人の好みに合わせて、テンプレートを自由にカスタマイズしてください。不要なセクションは削除し、必要なセクションは追加することが可能です。

## フォルダ構造（推奨）

プロジェクトフォルダは以下の構造になることを推奨します:

```
docs/
└ my-app/
   ├── 01-planning.md                  # プロジェクト計画書
   ├── 10-requirements.md              # 要件定義書
   ├── 20-mvp-requirements.md          # MVP要件定義書
   ├── 30-basic-design.md              # 基本設計書
   ├── 40-development.md               # 開発管理ルール
   ├── 41-sprint-backlog.md            # スプリントバックログテンプレート
   ├── 42-task-management.md           # タスク詳細管理テンプレート
   ├── 45-feature-design-doc.template.md  # 機能設計書テンプレート
   ├── 50-testing.md                   # テスト計画書
   ├── 60-deployment.md                # デプロイメント計画書
   ├── README.md                       # 本ファイル
   ├── sprints/                        # スプリント関連ドキュメント
   │   ├── 01/                         # スプリント1
   │   │   ├── sprint-01-backlog.md    # スプリント1バックログ
   │   │   └── task-01-F001.md         # タスク詳細
   │   └── 02/                         # スプリント2
   │       └── ...
   └── features/                       # 機能別設計書
      ├── feature-auth.md             # 認証機能設計書
      └── ...
```

## ベストプラクティス

1. **継続的な更新**: 開発の進行に合わせてドキュメントを継続的に更新しましょう
2. **シンプルに保つ**: 必要最低限の情報を明確に記録し、過剰な文書化は避けましょう
3. **振り返りの実施**: 各スプリント終了時に振り返りを行い、プロセスを改善しましょう
4. **問題と解決策の記録**: 発生した問題とその解決策を記録し、知識ベースとして活用しましょう
