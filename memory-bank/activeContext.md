## 6. 学習と洞察

- `gh pr create` コマンドで本文を渡す際、シェルの解釈によるエラーを避けるためには `--body-file` オプションで一時ファイルを渡すのが確実。
- プルリクエスト作成前に `git push` が必要。
- コミットメッセージ規約の遵守が重要。
- Android結合テスト実行には NDK バージョンと Core Library Desugaring の設定が必要な場合がある。
- **ワークフロー:** プルリクエストの作成/編集前には、必ずメモリバンクの確認・更新を行うことがユーザー様から求められている。
- **ブランチ戦略:** マージ先ブランチ (`feature/{機能ID}-base`) がリモートに存在しない場合は、先にpushしてからPRを作成する必要がある。
- **レビュープロセス:** PRに対するレビューコメントは、対応完了後も履歴として残し、どのような修正を行ったかの記録を残すことが重要。
- **コード構造:** メソッドでウィジェットを構築するよりも、個別のクラスに分けた方がコードの再利用性と可読性が向上する。
- **状態管理:** 手動で状態クラスを実装するよりも、freezedパッケージを使うことで安全性とボイラープレート削減が可能。
